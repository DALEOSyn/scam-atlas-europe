# T-4.6 Performance budget audit, 2026-11-20

Reviewer: `frontend-engineer` (read-only audit). Build: `main` at b42783b (detached worktree), `npm run build`, Vite 8.3.8, vite-plugin-pwa 2.0.0.
Browser: Chromium 1243 (`/opt/pw-browsers/chromium-1243`), headless, `--no-sandbox`, Pixel 7 emulation. Lighthouse 13.6.0 (installed in a scratch folder, not in the repo).

**Verdict: PASS on every budget in the repo. Three should-fix problems before G4:**
- Offline readiness is slow and fragile on mobile (P1).
- Resuming a run loads scenario chunks one after another (P2).
- One layout shift comes from the payee check (P3).

None of these blocks play. P1 matters most, because offline play is a stated feature.

## 1. Method

- **Server.** A small static server that behaves like GitHub Pages: gzip, `Cache-Control: max-age=600`, and `index.html` as the fallback. `vite preview` sends no compression, so it would understate transfer size.
- **Slow 4G.** Shaped at the server, so service-worker fetches are throttled too. CDP network emulation does not reach the service worker. Settings: 562 ms request latency and 1,474 kbit/s shared down-link, which is Lighthouse's DevTools "Slow 4G". HTTP/1.1, so Chrome opens at most 6 connections.
- **CPU.** CDP `Emulation.setCPUThrottlingRate`, 1x and 4x. The Lighthouse benchmark index of this machine is 1,910.
- **Vitals.**
  - LCP, CLS and Event Timing come from `PerformanceObserver` in an init script.
  - The INP-like figure is the longest Event Timing entry for each `interactionId`, from trusted Playwright clicks.
  - The SPA has no soft-navigation LCP, so a scene or device is measured as click → content visible → every `<img>` decoded.
- **Long play.** A generic auto-player drives the real production build, not the fixture harness. It always takes the first option on a scene, the chapter intro, a device, damage control or the chapter end. It played 5 chapters (Home, Berlin, Stockholm, Dublin, Lisbon; 298 steps). After each chapter it forced GC and read `Performance.getMetrics`.
- **Scripts.** Kept outside the repo in the session scratchpad: `sizes.mjs`, `serve*.mjs`, `measure.mjs`, `transitions.mjs`, `resume2.mjs`, `offline*.mjs`, `longplay.mjs`, `pwa*.mjs`. They are not committed. Ask if they should go into `scripts/perf/`.

## 8. Problems, file:line, suggested fix

**P1 (should-fix): offline readiness takes about 2 minutes on mobile, and the first-visit tab is never controlled.**
- **Where:**
  - `vite.config.ts:86-96` (the `workbox` block): no `clientsClaim`. 229 precache entries.
  - `dist/workbox-*.js`: precache install fetches entries one by one (`for (…) await Promise.all(handleAll…)`), so every entry costs a full round trip.
- **Effect:**
  - A player who installs or goes offline in the first minutes has an incomplete cache.
  - A player who stays on the first-visit tab is served from the network, not the SW. Offline play then depends on the HTTP cache: GitHub Pages `max-age=600`, so about 10 minutes.
- **Fix:**
  1. Add `clientsClaim: true` (with the existing `skipWaiting` from `autoUpdate`).
  2. Cut the entry count. Group lazy content per chapter: `build.rollupOptions.output.manualChunks` keyed on `content/(scenarios|scenes)/<city>/`, or one `import.meta.glob` per chapter module. That gives about 13 chapter chunks instead of 152. Concatenated gzip is also 40 % smaller (Brussels 29.5 → 16.8 KB).
  3. Optionally inline brand marks (27 tiny SVGs, 13 KB gzip) into one sprite or a JSON module. Drop `includeAssets: ['icon.svg']` (`vite.config.ts:73`) to remove the duplicate entries.
  4. Expected result: about 90 entries, or about 60 with brand marks inlined. Precache drops from about 134 s to about 35–55 s at these settings.
- **Test:** add an e2e check that the page is controlled after the first `ready`, then plays a scene while offline in the same tab.

**P2 (should-fix): `loadScenario` loads the city's scenarios one after another until the id matches.**
- **Where:** `src/app.tsx:116-121` (`for (const ref of …) { const s = await ref.load(); if (s.id === id) … }`). Callers:
  - `src/app.tsx:449`: each scenario in `next()`.
  - `:337`: the boss on chapter end.
  - `:370`: `slotTells`, all arc beats for the finale timeline.
  - `:451`: an arc beat borrowed from another chapter.
- **Effect:** arc files sort after the numbered files (`berlin-arc-…` > `berlin-09-…`), so the arc beat is always loaded last.
- **Measured** (Slow 4G, 4x, cold, resuming a saved Berlin run from the title):

  | Resume point | Time | Chunks |
  |---|---:|---:|
  | Run index 1 | 1.5 s | 2 |
  | Index 5 | 4.1 s | 6 |
  | Index 9 (boss) | 5.6 s | 9 |
  | Index 7 (arc beat) | **6.2 s** | **10** |

  - **Finale timeline (from reading the code, not measured):** `slotTells` does the same for every chapter's arc beat, so the cold finale loads close to every scenario chunk in the game, one after another.
- **Fix:** content:validate already enforces that file name equals id. Select the ref directly: `listScenarios().find((r) => r.chapter === city && r.file === `${id}.yaml`)?.load()`. Then build the ref list once instead of rebuilding and sorting it on every call. Optionally prefetch the next scenario's chunk while the debrief is on screen, which removes the 0.85 s cold "Start → device" wait from §4.

**P3 (minor): layout shift 0.058 when the payee check finishes.**
- **Where:** `src/ui/devices/Device.tsx:994` (an 800 ms "Checking…" timer). Then `:1013-1040` inserts the footer, coach mark and action list. They push `#options` (and `#demo-note`) down outside the 500 ms input window. Seen on "Banking app: payment to Róisín Byrne" (0.058) and "payment to Ellisfen Invest" (0.020).
- **Fix:** while `checking`, render the same footer and action list with `visibility: hidden` and `aria-hidden`, and keep focus behaviour as it is. Or give the card a `min-height` that holds its final size, so the result replaces the placeholder in place. With reduced motion the delay is already 0.

**P4 (minor): manifest and page metadata.** `index.html:8` `theme-color #fbf6ec` does not match `vite.config.ts:83` `#0f1b2d`; pick one. Add a maskable icon, either a PNG pair or an SVG with safe-zone padding and `purpose: "maskable"`. Add the iOS home-screen (touch) icon link.

**P5 (note, no action needed now): shell budget headroom.**
- **Size.** The shell is 105.8 KB gzip against 300 KB. `where-to-report.en.yaml` (6.4 KB gzip) is in the shell, and **should stay there**: help and crisis cards must open even when a lazy chunk cannot load.
- **Optional split.** `Device.tsx` and `ScenarioView.tsx` (about 14 KB gzip together) could be split from the title and map path. The gain is about 0.1 s on a cold Slow 4G load, so this is optional.
- **Recommendation.** Tighten the guard (below) so drift shows up.
